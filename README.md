# 保管形式判定くん

倉庫の商品について、**在庫定数**・**フリー在庫**・**収納上限**をもとに、適切な **主保管**（小箱／箱／コンテナ）と **予備保管**（なし／コンテナ）を自動判定する社内ツールです。

依存パッケージなしの単一HTMLファイルです。`index.html` をブラウザで開くだけで動作します。

## 公開URL（GitHub Pages）

`https://<ユーザー名>.github.io/hokan-hantei-kun/`

初回のみ、リポジトリの **Settings → Pages** で以下を設定します。

1. **Source** を `Deploy from a branch` にする
2. **Branch** を `main` / `/ (root)` にして **Save**
3. 1〜2分待つと、同じ画面の上部に公開URLが表示される

以後は `main` に push するたびに自動で反映されます。

## 判定の考え方

```
判定用在庫数 ＝ MAX（在庫定数, フリー在庫）
```

「通常持っておきたい数量」と「実際に場所を取っている数量」のうち多い方で判定します。

### 基礎区分ごとの保管ルート

| 基礎区分 | 使用できる状態 |
| --- | --- |
| 小箱-多収納 / 小箱-少収納 | 主：小箱 → 主：箱 → 主：箱＋予備：コンテナ |
| 箱-多収納 / 箱-少収納 | 主：箱 → 主：箱＋予備：コンテナ |
| コンテナ | 主：コンテナ（固定） |

### 昇格・降格・予備保管

- **昇格**：`判定用在庫数 ＞ 現在の主保管上限`。ちょうど100%は維持。
- **降格**：`判定用在庫数 ＜ 現在の主保管上限 × 50%` かつ `判定用在庫数 ≦ 降格先の上限` の**両方**を満たす場合のみ。ちょうど50%は維持。降格先に収まらなければ降格しない。
- **予備コンテナ追加**：主保管が箱で `判定用在庫数 ＞ 箱上限`。
- **予備コンテナ解除**：`判定用在庫数 ≦ 箱上限`。
- いずれも1段階ずつ止めず、**最終的に適切な主保管＋予備保管の組み合わせまで一気に判定**します。

### 収納上限の初期値

| 基礎区分 | 小箱上限 | 箱上限 |
| --- | --- | --- |
| 小箱-多収納 | 150 | 750 |
| 小箱-少収納 | 30 | 150 |
| 箱-多収納 | ― | 190 |
| 箱-少収納 | ― | 40 |
| コンテナ | ― | ― |

基礎区分ごとに初期値を自動設定し、SKU単位で上書きできます。上書きしたSKUには「個別」タグが付き、以降はそのSKUの値を使用します。

### 有効な保管の組み合わせ

| 主保管 | 予備保管 | 有効 |
| --- | --- | --- |
| 小箱 | なし | ○ |
| 箱 | なし | ○ |
| 箱 | コンテナ | ○ |
| コンテナ | なし | ○ |
| 小箱 | コンテナ | × |
| コンテナ | コンテナ | × |

### 要確認になる条件

在庫定数・フリー在庫の未取得、必要な収納上限の未入力、小箱上限＞箱上限、マイナス値、基礎区分と現在の主保管の矛盾、無効な主保管＋予備保管の組み合わせ、API商品照合エラー。
これらは自動判定を行わず「要確認」と表示します（**不足データを0として扱いません**）。

## 月次の運用フロー

1. NE同期を実行（毎朝7:00に自動実行。すぐ更新したい場合は「ネクストエンジンから最新データを取得」）
2. GitHub Actions が ne-sync-worker から在庫定数・フリー在庫を取得し、data.json を更新
3. ツールを開く（または「共有データを再読み込み」）と、判定用在庫数が自動計算される
4. 全SKUの推奨主保管・推奨予備保管・判定結果・判定理由・変更要否を自動再計算
5. 変更対象一覧（変更要否＝要）を確認
6. 倉庫で移動作業
7. 現在の主保管・現在の予備保管を更新し、対応状況を「対応済」にする

## ネクストエンジン連携（ne-sync-worker 経由）

在庫定数とフリー在庫は、**GitHub Actions（サーバー側）が `ne-sync-worker` から取得**して `data.json` に書き込みます。
ブラウザからネクストエンジンや worker を直接呼ぶことはなく、`NE_READ_API_TOKEN` が公開ページに出ることはありません。
ネクストエンジンの認証（access token / refresh token）は worker 側が持っているため、このアプリでは実装しません。

```
GitHub Actions ──POST──▶ ne-sync-worker ──▶ ネクストエンジン
   （Secret を使用）        /api/ne/inventory
        │
        └─▶ data.json を更新してコミット ──▶ 各PCのブラウザが読む
```

### 初期設定（1回だけ）

リポジトリの **Settings → Secrets and variables → Actions** で登録します。

| 種別 | 名前 | 値 |
| --- | --- | --- |
| **Secrets** タブ → New repository secret | `NE_READ_API_TOKEN` | worker のリードトークン |
| **Variables** タブ → New repository variable | `NE_SYNC_URL` | `https://ne-sync-worker.…/api/ne/inventory` |

`NE_SYNC_URL` は Secrets 側に登録しても動きます（エンドポイントを公開リポジトリに残したくないため、コードには書いていません）。

### 実行タイミング

- **自動**：毎朝 7:00（日本時間）
- **手動**：ツールの「ネクストエンジンから最新データを取得」ボタン
  （トークンの権限に **Actions: Read and write** が必要です。無い場合はボタンから Actions の画面が案内されます）
- **手動（GitHub上）**：Actions タブ → 「NE同期」 → Run workflow

実行後1〜2分で `data.json` が更新され、各PCは「共有データを再読み込み」で反映されます。

### 取得の仕様

- `data.json` にある商品コードだけを worker に問い合わせます（1リクエスト最大1000件、超える分は自動で分割）
- `free_stock` → フリー在庫、`stock_constant` → 在庫定数
- **取得できなかった商品を0に置き換えることはしません。** 前回取得値を残し、画面に「前回値」と表示します
- 一度も取得できていない商品（NEに存在しない商品コードなど）は、判定を行わず **要確認** にします
- ツール独自データ（基礎区分・収納上限・現在の主保管／予備保管・対応状況・備考）は同期で上書きされません
- 今後NEから別の項目が必要になった場合は、`ne-sync-worker` 側にAPIを追加する方針とし、このアプリでNE認証は実装しません

### 関連ファイル

```
.github/workflows/ne-sync.yml   毎朝の自動実行と手動実行
scripts/ne-sync.mjs             worker を呼んで data.json を更新する処理
```

## （参考）ネクストエンジンAPIを直接使う場合

将来 `ne-sync-worker` を使わずに実装する場合の参考情報です。**現在の構成では使いません。**

| 用途 | エンドポイント | 主なフィールド |
| --- | --- | --- |
| 在庫定数の取得 | `POST /api_v1_master_goods/search` | `goods_id`, `goods_name`, `goods_stock_constant` |
| フリー在庫の取得 | `POST /api_v1_master_stock/search` | `stock_goods_id`, `stock_free_quantity`, `stock_last_modified_date` |

その場合も `client_secret` / `access_token` / `refresh_token` はサーバー側で保持し、フロントエンドに埋め込まないこと。
複数倉庫のうち特定倉庫だけで判定する必要が出た場合は、拠点在庫マスタ（`warehouse_stock_free_quantity`）への切り替えを検討します。

## データの持ち方

商品データは、このリポジトリの **`data.json`** を全員が読む形にしています。

- 公開URLを開くと、必ず `data.json` の内容が表示されます。**スタッフ全員が同じデータを見ます。**
- 画面上で編集した内容は、その人のブラウザ内にだけ保存されます（他の人には反映されません）。
  この状態のときは共有データ欄に「**この端末だけの変更あり**」と表示されます。
- 「共有データを再読み込み」を押すと、`data.json` の内容に戻ります。

### スタッフの使い方

公開URLを開くだけです。GitHubのアカウントもインストールも不要です。
「変更対象一覧」タブを見れば、今月どの商品をどこへ動かすかが分かります。

### 担当者がデータを更新する手順

**A. トークンを設定している場合（おすすめ）**

1. 公開URLを開く
2. CSVを取り込む、または画面上で編集する
3. **「GitHubに保存して全員に反映」** を押す
4. 他のPCは再読み込みするだけで最新データになります（数秒）

**B. トークンを使わない場合**

1. 「共有用JSONを書き出す」を押して `data.json` をダウンロード
2. GitHubで `data.json` を開き、鉛筆アイコン → 中身を貼り替えて **Commit changes**
3. 他のPCは再読み込みで最新データになります

`data.json` が更新されると、各PCに残っていたローカルの変更は最新の共有データで置き換えられます。

## 複数PCから保存できるようにする（Personal Access Token）

「GitHubに保存して全員に反映」を使うには、**保存する人のPCごとに** GitHubのトークンを設定します。
閲覧するだけのスタッフには不要です。

### トークンの作り方

1. GitHub → 右上のアイコン → **Settings** → 左メニュー最下部の **Developer settings**
2. **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
3. **Repository access**：`Only select repositories` を選び、このリポジトリだけを指定
4. **Permissions** → Repository permissions → **Contents** を **Read and write** に変更
5. **Expiration**（期限）を決めて **Generate token**
6. 表示された文字列をコピー（この画面を閉じると二度と表示されません）

### ツール側の設定

1. ツールの上部にある **「保存設定」** を開く
2. オーナー・リポジトリ名・ブランチ・ファイル名を確認（既定値のままでOK）
3. トークンを貼り付けて **「接続を確認して保存」**
4. 成功すると **「GitHubに保存して全員に反映」** ボタンが出ます

### 安全のための決まりごと

- トークンは**そのブラウザの中だけ**に保存されます。CSVにも `data.json` にも含まれません。
- **リポジトリのファイルに絶対に貼り付けないこと。** このリポジトリはPublicなので、誰でも読める状態になります（GitHubが検知して自動で無効化します）。
- 共用PCや、他の人も触るブラウザには設定しないでください。
- 権限は **Contents: Read and write** だけで足ります。それ以上は付けないでください。
- 使わなくなったら、GitHubの Developer settings から **Revoke**（失効）してください。ツール側の「トークンを削除」はそのPCから消すだけで、GitHub側では有効なままです。
- 期限が切れたら、新しく作り直して「保存設定」で入れ直します。

### 同時に保存したとき

ほかのPCが先に保存していた場合、保存は失敗して「先に保存されました」と表示されます。
**「共有データを再読み込み」** で最新を取り込んでから、もう一度編集して保存してください（上書きで消えることはありません）。

### CSVの形式

1行目の見出しは以下のとおりです。商品コード以外は空欄でも構いません。

```csv
商品コード,商品名,基礎区分,小箱上限,箱上限,現在の主保管,現在の予備保管,在庫定数,フリー在庫,対応状況,備考
ABC-001,USB-C ケーブル 1m,小箱-多収納,100,500,小箱,なし,200,150,未対応,
BOX-021,ペットフード 5kg,箱-少収納,,40,箱,なし,60,55,未対応,
```

- 基礎区分：`小箱-多収納` / `小箱-少収納` / `箱-多収納` / `箱-少収納` / `コンテナ`
- 現在の主保管：`小箱` / `箱` / `コンテナ`　現在の予備保管：`なし` / `コンテナ`
- 収納上限を空欄にすると、基礎区分ごとの初期値が入ります
- Excelから書き出したCSV（Shift_JIS）もそのまま取り込めます

> このリポジトリは Public です。`data.json` に入れた商品コード・在庫数は誰でも見られます。
> 公開したくない情報が含まれる場合は、リポジトリを Private にしてください（Settings → General → Danger Zone → Change repository visibility）。
> ネクストエンジンの認証情報は絶対にコミットしないでください。
