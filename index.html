固定保管の昇格・降格は**在庫定数だけ**で判定する。フリー在庫は使わない。 - 共用コンテナバッファは**SKUの固定保管場所として保存しない**。`小箱＋コンテナ` `箱＋コンテナ` は存在しない。 - MAX（在庫定数, フリー在庫）は画面に参考表示するだけ。**判定基準にしない。** ### 2-1. 基礎区分と上限 判定は**区分名に依存せず**、「ルート」と「SKUごとの小箱上限・箱上限」だけで行う。 ```js const KUBUN_DEFS = [ { name:'小箱-少収納', route:'小箱', smallCap:30, boxCap:150 }, { name:'小箱-多収納', route:'小箱', smallCap:150, boxCap:750 }, { name:'箱-少収納', route:'箱', smallCap:null, boxCap:40 }, { name:'箱-多収納', route:'箱', smallCap:null, boxCap:190 }, { name:'コンテナ', route:'コンテナ', smallCap:null, boxCap:null } ]; const ROUTE_CHAIN = { '小箱':['小箱','箱'], '箱':['箱'], 'コンテナ':['コンテナ'] }; ``` 通常商品のルートは **小箱 ⇔ 箱** だけ。在庫が増えても固定コンテナへ昇格させない。 コンテナ固定は、もともとコンテナ保管が必要な商品だけ（在庫の増減で他へ変えない）。 3分類へ統合するときは `KUBUN_DEFS` を書き換え、`KUBUN_ALIAS` に旧名称→新名称を入れるだけ。 ### 2-2. 固定保管の判定 | 判定結果 | 条件 | |---|---| | **昇格**（小箱→箱） | 在庫定数 ＞ 小箱上限（ちょうど100%は維持） | | **降格**（箱→小箱） | ①在庫定数 ＜ **箱上限**×50% ②在庫定数 ≦ 小箱上限　の**両方**（ちょうど50%は降格しない） | | **箱上限超過** | 在庫定数 ＞ 箱上限。**推奨は「箱」のまま**。固定コンテナへ自動昇格させない | | **維持** | 上記以外 | | **要確認** | validate() がエラーを返したとき | - 箱区分（`箱-少収納` `箱-多収納`）は小箱上限を持たないので、降格しない。 - コンテナ区分は在庫数に関わらず固定保管コンテナ。 ### 2-3. バッファ判定 ``` 使用候補 ⟺ フリー在庫 ＞ 現在の固定保管の収納上限 超過数量 = MAX(フリー在庫 − 現在の固定保管の収納上限, 0) ``` **「現在の」固定保管の上限**で見るのが重要。昇格待ちのSKUは、実際に移動するまで小箱に入りきらないので使用候補になる。 コンテナ固定商品は常に「不要」。 ### 2-4. 上限設定状態 `仮設定`（基礎区分の初期値のまま） / `SKU確認済`（実測済み）。既定は `仮設定`。 基礎区分を変えると上限が初期値に戻るので、`capState` も `仮設定` に戻す。 ### 2-5. 要確認になる条件（`validate()`） 在庫定数・フリー在庫の未取得、必要な収納上限の未入力、小箱上限＞箱上限、マイナス値、 基礎区分と現在の固定保管の矛盾、API商品照合エラー。**不足データを0として扱わない。** ## 3. ファイル構成 ``` hokan-hantei-kun/ ← GitHub リポジトリの中身 ├── index.html ← 本体（納品するのはこれだけ） ├── data.json ← 共有データ（現在は空。ユーザーが「GitHubに保存」で1195件を入れる予定） ├── README.md ← 運用マニュアル（判定ルール／PAT設定／NE連携） ├── .gitignore ├── scripts/ │ └── ne-sync.mjs ← Actions側でNEから在庫を取得し data.json を更新 ├── .github/workflows/ │ └── ne-sync.yml ← 毎朝7時(JST)に自動実行 ＋ 手動実行 └── docs/仕様書.txt ← 元の仕様書（在庫保管形式管理ツール.txt） logo/ ← ロゴ素材（A案採用：箱＋青い双方向矢印） tests/ ← 検証用スクリプト（Playwright） 商品リスト_テンプレート.csv ← CSV取り込み用テンプレート ``` ### index.html の主要な定数（場所の目印） | 定数 | 内容 | |---|---| | `APP_VERSION` | 画面右上のバージョン表示。**更新のたびに +1** | | `LS = 'hokan-hantei-kun-v2'` | 本体データの localStorage キー | | `GH_LS = 'hokan-hantei-kun-github'` | GitHub設定（PAT含む）の localStorage キー | | `KUBUN_DEFS` / `ROUTE_CHAIN` | 基礎区分と上限 | | `CSV_COLS` | CSVの列定義 | | `judge(it)` | 判定ロジック本体 | | `buildXlsx()` / `exportXlsx()` | Excel出力（ZIP・OOXMLを自前生成） | --- ## 4. データの流れ ``` ネクストエンジン │ (ne-sync-worker 経由。トークンは Actions の Secret のみ) ▼ GitHub Actions「NE同期」 ── scripts/ne-sync.mjs ──▶ data.json を更新・コミット │ raw.githubusercontent.com ▼ ブラウザのツール ──「共有データを再読み込み」で取り込む │ 「GitHubに保存」(PAT) で data.json を上書き ``` -
